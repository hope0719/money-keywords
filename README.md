# money-keywords

围绕一个方向，从谷歌趋势里找出刚涨起来的英文搜索词，再看谷歌前 20 名里有没有近一年注册的新站排上去、它们在做什么、怎么收费，最后押三个词：对标站、第一版做什么、注册什么域名。

## 这套方法在做什么

核心判断只有一句：**先找新词，再找新站。**

1. **新词**——新词在谷歌趋势里当天就能看到，关键词工具的月度数据要晚一两个月。所以先用趋势把范围收窄。
2. **新站**——谷歌真实排名只能靠浏览器一页一页看。一个新注册的域名已经排进前 10，说明新来的人进得去；它怎么收费，是这件事收不收得到钱的参照。

「已经有人做了」不否决，看的是竞争激不激烈。

完整规则在 [`SKILL.md`](SKILL.md)，十步流程：出词根 → 找候选 → 划掉不要的 → 量热度判新旧 → 看前 20 名 → 看站怎么收费 → 打分 → 挑刺 → 押注 → 交报告。

## 本仓库做了什么

原版是方法论层面的完整作品，但在**本机部署**时有两类工程问题：凭证找不到、装完不知道能不能用。改动集中在运行层，不触碰任何判定规则。

| # | 改动 | 类型 | 解决的问题 |
|---|---|---|---|
| 1 | `scripts/dfs.py` 新增 `env_search_paths()`，`creds()` 改为按优先级查找 5 个位置 | 修补 | **原版只认「当前工作目录」的 `.env`**，从别处用绝对路径调用脚本时凭证永远找不到，整套付费查询跑不起来 |
| 2 | `scripts/healthcheck.py` | 新增 | 装完无法判断能不能用、配错也不知道错在哪 |
| 3 | `references/本地部署与快速开始.md` | 新增 | 没配 DataForSEO 时怎么 0 成本跑完十步；`.env` 放哪；故障对照表 |
| 4 | `SKILL.md` 插入「开工前自检」一节，改两处凭证说明 | 修补 | 把自检前置；三档强度并列，并明确「三档的判断标准完全一样」，防止在轻量档下擅自降低打分门槛 |

改动可用补丁反向应用或重放：

```bash
patch -p1 -R < patches/01-dfs-multi-env-lookup.patch   # 还原为原版
patch -p1 -R < patches/02-skillmd-preflight.patch
```

逐条说明见 [`LOCAL-CHANGES.md`](LOCAL-CHANGES.md)。

### 没有改的东西

- **没有压缩 `SKILL.md` 正文。** 685 行里那些「实测」数字是判定力的来源——比如「为什么在两个和四个月之间单分一档」，是作者拿一个差 9 天的真实案例验出来的。删掉这些，规则就失去了依据。
- **没有改动任何评分阈值、档位定义、判定标准。**
- **没有碰 `manifest.json`。** 它的 `files[].sha256` 校验的是原始文件，本地改动后不一致；这只影响服务端的变更检测，不影响本机运行。

## 快速开始

要求：Python 3.8+，**不需要 `pip install` 任何东西**（全部脚本只用标准库）。

```bash
# 1. 自检：一条命令看当前环境能不能用
python3 scripts/healthcheck.py

# 2. 可选：配 DataForSEO，拿到具体的月搜索量
cat > .env <<'EOF'
DATAFORSEO_LOGIN=你的登录名
DATAFORSEO_PASSWORD=你的密码
EOF
chmod 600 .env
```

自检会查六项：Python 版本、文件完整性、脚本语法、是否只依赖标准库、凭证是否有效（并读出余额）、四个数据源连通性。

**没配 DataForSEO 也能跑完整套流程**，只是搜索量改用趋势比大小和档位区间：

| 档 | 花钱 | 词根 | 看前 20 名的词 | 量的精度 |
|---|---|---|---|---|
| 轻量 | $0 | 5–8 个 | 5–8 个 | 档位 / 趋势粗估 |
| 标准 | 约 $0.4 | 8–15 个 | 10–15 个 | 月搜索量具体数字 |
| 完整 | 约 $1–1.5 | +滚雪球 | 10–15 个 | +点击流校正 |

三档的**判断标准完全一样**，只是查得多查得少。具体每步的命令和网址见 [`references/本地部署与快速开始.md`](references/本地部署与快速开始.md)。

## 已知限制

- **谷歌排名只能靠浏览器看。** 任何接口返回的名次都不能用——原文档记录过实测：DataForSEO 的结果接口一次取 20 条时，和浏览器真实第一页的重合是 **0**。本仓库保留了这个结论。
- **`whois_date.py` 与 `domain_check.py` 会访问公开服务**，批量查会被限流，脚本内置 0.6 秒间隔，再多要分批。
- **`dfs.py` 按次计费**（`related` 约 $0.011/次，`volume` 一批约 $0.09），每跑一条命令会把实际花费记进当前目录的 `花费.tsv`。
- **`google_top20.js` 不是命令行脚本**，要在已打开的谷歌结果页里注入运行。
