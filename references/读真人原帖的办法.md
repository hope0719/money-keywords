# 去哪读真人原帖，读不到怎么办

找差别、从抱怨里找词，都要读真人发的求助帖。最容易卡住的就是这一步：搜索引擎搜回来的多是卖工具的博客，真人的帖子反而打不开。
按下面的顺序试，上一条走不通就换下一条。

## 一、先分清什么算「读到了」

- 算：打开了帖子，读到了发帖人自己写的正文。
- 不算：只看到搜索结果里的标题和摘要；只看到别人文章里转述的一句话；页面显示要登录才能看正文。

不算的不要拿来用，更不要凭标题猜正文。

## 二、Reddit

生活类、办公类产品的求助，大多在这里。

1. AI 自己能打开 Reddit 的，直接读。
2. **AI 打不开时，请用户自己读了贴过来。这是最稳的办法。** 只在用户点名要从抱怨里找词时才停下来请他贴；给排在前面的词找差别时不停，读不到就照 SKILL.md「做不了时怎么办」处理。 很多 AI 工具打不开 Reddit，但用户自己的浏览器能开。告诉用户：
   - 去 Reddit 搜「产品名 alternative」或「平台名 加 动作」，或者在搜索引擎里搜同样的词再加上 `site:reddit.com`。
   - 挑真人在求助的帖子（不是在推自己产品的），把帖子链接、发帖日期、正文全文复制给你。一次贴五到十帖。回复不用全贴，贴点赞最多的三五条，再加上发帖人自己后来的回复。

   对用户可以这样说：

   > 我打不开 Reddit，需要你帮我搜一下。请在 Reddit 的搜索框里搜下面这几个词，每个词挑两三帖真人在求助的（标题不是在介绍自己做的产品），把每一帖的链接、发帖日期、正文整段复制给我，再带上点赞最多的三五条回复，和发帖人自己后来的回复。
3. 手头有能读 Reddit 的数据接口，或者有能联网读 Reddit 的 AI（例如 Grok），可以用。让别的 AI 找的，要它给链接、日期、标题和原文摘录，拿回来抽几条核对。

## 三、X

平台自己的规则、创作者拿钱、新出的功能这类方向，真人多半在 X 上问，不在 Reddit 上。

1. 用能搜 X 的 AI 搜，比如 Grok；或者请用户自己用 X 的高级搜索。搜近 30 天、带着方向主词的帖子，要它给账号、日期、链接、原话，并标出哪些是在抱怨。
2. AI 给的帖子只当线索。要引用的，逐条回原帖核对原话和日期：浏览器里打开链接看；能运行命令的，可以取 `https://api.fxtwitter.com/账号/status/帖子编号`，公开、不用登录。核对不上的不用。
3. 浏览量只有几十的帖子也可以用。要的是他原话里卡在哪，不是这条帖子火不火。

你搜不了 X、用户也不方便搜的，这一节跳过，写「X 没搜」，照下面几节去别处读。

实测一个平台的创作者奖励计划：用上的 12 条原话全是 X 上的，逐条回读都对得上；Reddit 一条没用上。

## 四、Hacker News

AI 用命令行就能读，不用登录。偏程序员和开发者工具，生活类、办公类的少。

搜近一年的求助帖（日期范围在运行时计算，不沿用旧实验时间戳）：

```
python3 - <<'PY'
import datetime, json, urllib.parse, urllib.request
since = int((datetime.datetime.now(datetime.timezone.utc) - datetime.timedelta(days=365)).timestamp())
params = {'query': 'alternative', 'tags': 'ask_hn', 'numericFilters': f'created_at_i>{since}', 'hitsPerPage': 50}
url = 'https://hn.algolia.com/api/v1/search_by_date?' + urllib.parse.urlencode(params)
print(json.dumps(json.load(urllib.request.urlopen(url, timeout=30)), ensure_ascii=False))
PY
```

读某一帖的正文和全部评论（把数字换成帖子编号）：

```
curl -s "https://hn.algolia.com/api/v1/items/44080225"
```

- `%3E` 是大于号，不能直接写 `>`。
- 只搜 alternative 一个词，回来的大半不相关。换着搜：`alternative to`、`replacement for`、`looking for`、`shutting down`、具体的产品名。
- 长的词组搜不到东西，一次只放两三个词。

## 五、论坛

- **用 Discourse 搭的论坛。** 很多产品的官方论坛是这种。在论坛地址后面加 `/search.json?q=关键词` 能搜出带日期的帖子，再用 `/t/帖子编号.json` 读正文。判断是不是 Discourse：试一下这个地址，回来是一段数据就是。
- **做自动化的工具的社区。** Make、Zapier、n8n 的社区是公开的。卖家、小生意的人想把平台里的数据弄出来，常常去这些地方问「怎么把某平台的某东西导进表格」。帖子里的话技术味重，但背后是真需求。
- **平台自己的官方社区。** 有的能读（Shopify 社区、Apple 社区、Obsidian 论坛），有的老帖要登录才显示正文（Etsy 社区的旧地址）。要登录的就放弃，换别处。
- **垂直论坛。** 电子书、摄影、3D 打印这些都有自己的老论坛，多数公开。

## 六、都走不通

给排在前面的词找差别时：不停下来等用户。只看前排站官网写明的限制；都没有，差别写「没查到」，并写明试了哪几处、各是什么结果。帖子读到了正文但回复没读到的，只按正文用，写「回复没读到」。

用户点名要从抱怨里找词时：如实告诉他试了哪几处，请他自己去 Reddit 或常去的社群里看，把帖子贴过来。

不要因为找不到，就拿博客文章、厂商的对比页、自己编的句子冒充真人原话。

## 找到的帖子怎么筛

下面几种不写成候选句：

- 发帖人不是真在求助，而是在介绍自己做的产品。标题里有「I built」「I made」，或者「产品名 – 一句介绍」，多半是推广，剔掉。
- 读回复，先找楼主自己后来的回复。已经有人贴了官方功能的用法、楼主也说解决了的，不要。回复没读全的（比如接口只给了前几条），在表里写「回复没读全」。
- 一年以前的帖子，先确认那个产品现在的状态。问题已经没了的，不要。
