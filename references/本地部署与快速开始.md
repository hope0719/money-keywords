# 本地部署与快速开始

这份是给「已经把 skill 装到本机、准备真的跑一轮」的人看的。SKILL.md 讲方法，这份讲**在这台机器上怎么让它跑起来**。

---

## 0. 先跑一次自检（30 秒，不花钱）

```bash
python3 scripts/healthcheck.py
```

它查六件事：Python 版本、文件齐不齐、脚本语法通不通、有没有 DataForSEO 凭证、四个数据源通不通、有没有代理。

**只有两种结论：**

- `✅ 可以开工` —— 直接往下走。有没有凭证都能跑，区别只是走哪一档。
- `⛔ 先修一下` —— 按红色那条的提示补，补完再跑一次。

离线或者不想等网络检查的，加 `--offline`。

## 1. 配 DataForSEO（可选，不配也能跑完）

配了它，月搜索量是**具体数字**；不配，量只有**趋势粗估和档位**。

在 [DataForSEO 后台](https://app.dataforseo.com/api-access) 的 API Access 页拿到接口登录名和密码，然后**任选一处**放 `.env`：

```bash
# 推荐：放 skill 根目录，以后换任何工作目录都不用重配
cat > ~/.workbuddy/skills/money-keywords/.env <<'EOF'
DATAFORSEO_LOGIN=你的登录名
DATAFORSEO_PASSWORD=你的密码
EOF
chmod 600 ~/.workbuddy/skills/money-keywords/.env
```

`dfs.py` 按这个顺序找，先找到的先用：

| 顺序 | 位置 | 什么时候用 |
|---|---|---|
| 1 | 当前工作目录的 `.env` | 想给某一轮单独用一套额度 |
| 2 | `scripts/.env` | 不常用 |
| 3 | **skill 根目录的 `.env`** | ← 推荐，一次配好长期有效 |
| 4 | skill 根目录的**真实路径**下的 `.env` | 用软链安装时（3 是软链路径、4 是它指向的真实目录），放进哪个都会命中 |
| 5 | `~/.workbuddy/secrets/dataforseo.env` | 想和其他工具共用 |

也可以用同名环境变量 `DATAFORSEO_LOGIN` / `DATAFORSEO_PASSWORD`，优先级最高。

配好再跑一次自检，会多一行「✅ 凭证有效，余额 $X」。

**关于花钱**：`related` / `compare` / `curve` 每次约 $0.011，`volume` 一批约 $0.09，`overview` 一批约 $0.03。标准一轮约 **$0.4**，完整一轮约 **$1–1.5**，其中看曲线占一半。每跑一条命令都会把实际花费记进**当前工作目录**的 `花费.tsv`，并在末尾打印本次和累计。

> 密码不要贴进对话，也不要写进报告。脚本只读那两行，不打印、不转存。

## 2. 三档强度，按你现在有多少时间选

| | 轻量一轮 | 标准一轮 | 完整一轮 |
|---|---|---|---|
| 用时 | 约 15 分钟 | 约 20 分钟 | 约 60 分钟 |
| 花钱 | **$0** | 约 $0.4 | 约 $1–1.5 |
| 要 DataForSEO | 不要 | 要 | 要 |
| 词根 | 5–8 个 | 8–15 个 | 8–15 个 + 滚雪球 3–5 个 |
| 看前 20 名的词 | 5–8 个 | 10–15 个 | 10–15 个 |
| 量的精度 | 档位 / 趋势粗估 | 月搜索量具体数字 | 具体数字 + 点击流校正 |
| 适合什么时候 | 先验证方向值不值得深挖 | 日常 | 要押注、要动手 |

三档的**判断标准完全一样**（第 3 步怎么划线、第 7 步怎么打分、第 8 步怎么挑刺），只是查得多查得少的区别。轻量一轮的结论会粗一些，但方向对不对、值不值得做，看得准。

## 3. 轻量一轮怎么完整跑完（0 成本）

没有 DataForSEO 时，只有两件事要换办法：**看趋势**和**量热度**。其余全靠 skill 自带的免费脚本。

### 第 1–2 步：出词根、找候选词

```bash
cd ~/.workbuddy/skills/money-keywords/scripts

# 谷歌下拉：每个词根一次，看冒出来什么说法
python3 suggest.py "ai generator" "ai video"

# 名字类的词根，后面加 a 到 z（一个词根发 27 次请求，最多对 5 个词根做）
python3 suggest.py --az "kling"

# 应用商店：近两个月上架了哪些同类应用
python3 appstore_new.py "ai video" "video generator"
```

**趋势改用浏览器看**，地址按这个格式拼（`gl=us&hl=en` 别省，否则可能落到中文界面）：

```
https://trends.google.com/trends/explore?date=now%207-d&geo=US&q=你的词根&hl=en
```

- 看页面下方**「相关查询」**：上升栏（Rising）全记，带涨幅；热门栏（Top）记前 10 个当参照。
- 上升栏不到 5 条的，把 `date=now%207-d` 换成 `date=now%2030-d` 再看一次；还少，把 `geo=US` 去掉看全球。
- **比大小**（一次最多 5 项，其中一个是尺子词）：

```
https://trends.google.com/trends/explore?date=now%2030-d&geo=US&q=你的词,personality%20test&hl=en
```

尺子词：`personality test`（美国每月约 18 万次），比小词时换 `image splitter`（约 1.4 万次）。候选词的线加起来是尺子词的几分之一，量就约是尺子月量的几分之一。

> ⚠️ **下拉只能用来找词，不能拿来估量。** 下拉里词的多少、先后，反映的是这个说法流不流行，不是搜索次数。量必须靠趋势比大小或者档位。

### 第 4 步：量热度、判新旧

- 量：浏览器比大小（上面那条 URL），或 Ahrefs 免费关键词生成器（国家选美国，量分五档，**照抄档位，不要编成具体数字**；有人机验证就跳过）。
- 判新旧：趋势页面把时间拉到「过去 12 个月」，看它从哪天开始有量；看不清拉到「过去 5 年」。
- 读数一直是 0 的，写「趋势里看不出」，**不要写成没人搜**。

### 第 5 步：看谷歌前 20 名（只能浏览器）

```
https://www.google.com/search?q=snow+day+calculator&gl=us&hl=en
```

第二页在末尾加 `&start=10`。**一个浏览器一轮控制在 30 次谷歌请求以内**；出现人机验证就停，不做验证。

```bash
# 取回来的排名存成文件（每个词以「## 词」开头），数数交给脚本
python3 serp_table.py domains 排名.txt      # 列出要查注册日期的独立站域名
python3 whois_date.py 域名1 域名2           # 查注册日期，免费、不用登录
python3 serp_table.py table 排名.txt 注册日期.txt   # 每个词一张表带小结
```

### 第 9 步：押注时查候选域名

```bash
python3 whois_date.py 候选1.com 候选2.app    # 先快速筛一遍有没有人注册
python3 domain_check.py 候选1.com            # 只对没人注册的做五项检查，一个约 15 秒
```

### 全程都不要做的事

- 不拿 AI 自带的联网搜索代替谷歌真实排名；
- 不拿 DataForSEO 的结果接口取谷歌排名（实测和浏览器重合是 0）；
- 不勾选、不做任何形式的人机验证。

## 4. 常见故障

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `no matches found` / `command not found` | 把自然语言或裸 URL 粘进了终端 | URL 要加引号并交给 `open` / `curl`，见文末 |
| `没有找到 DataForSEO 的凭证` | `.env` 不在查找路径里 | 放到 skill 根目录，或看报错里列出的那几个位置 |
| 凭证报 401 / 提示凭证无效 | 登录名密码不对，或复制时带了空格 | 去 API Access 页重新复制，注意别把 `:` 带进去 |
| 谷歌相关全部超时，其他正常 | 没走代理 | 设 `https_proxy`，先 `curl -I https://www.google.com` 验证 |
| 趋势页一直转圈 / 429 | 请求太密 | 隔几分钟再试，或把词根减到 5 个 |
| `whois_date.py` 批量查一半开始返回空 | 被限流 | 脚本每次间隔 0.6 秒，再多就分批跑，隔一会儿再来 |
| 谷歌结果页全是中文 | 浏览器自动翻译 | 先关翻译；关不掉按 `references/取谷歌前20名的办法.md` 在页面里重新取原文 |
| 注册商页面打不开 | 被墙或反爬 | 换一家注册商搜索页，价格项写「没查成」 |

## 5. 在终端里，什么能粘、什么不能粘

```bash
# ✅ 打开页面看一眼
open "https://trends.google.com/trends/explore?date=now%207-d&geo=US&q=calculator&hl=en"

# ✅ 读一份在线文档
curl -sL "https://scys.com/skillhub/llms/skillhub-install-guide.md" | less

# ⛔ 裸 URL 直接回车：? 会被当成通配符，& 会被当成后台执行
https://example.com/a?b=1&c=2
```

规矩一句话：**终端只认程序名**。开头那个词必须是 `open`、`curl`、`python3` 这类真实命令，URL 永远是用引号包起来的参数。

## 6. 升级会覆盖本地改动

用 SkillHub 的托管包方式安装时，入口软链指向 `versions/<版本号>`。升级到新版本后 `current` 会指向新目录，**上一版的本地改动不会跟过去**。

要重放的是三样：

1. `scripts/healthcheck.py`（新增文件）
2. `references/本地部署与快速开始.md`（新增文件）
3. `scripts/dfs.py` 的 `env_search_paths()` / `creds()`，以及 `SKILL.md` 里「开工前」那一节

后两样都在补丁里，先放好新增文件再打：

```bash
cp scripts/healthcheck.py                        <新版本目录>/scripts/
cp references/本地部署与快速开始.md                <新版本目录>/references/
patch -p1 -d <新版本目录> < patches/01-dfs-multi-env-lookup.patch
patch -p1 -d <新版本目录> < patches/02-skillmd-preflight.patch
```

回滚就是把两个补丁反向应用（`patch -p1 -R`），再删掉那两个新增文件。

要对比改动前后，拿原始 1.0.1 当基线：

```bash
diff -ru .original-1.0.1 <当前目录>
```
